# Poppy — the app

This folder is the Poppy app: a **Vite + React** Progressive Web App. Once deployed over HTTPS it installs to your phone's home screen and runs full-screen, offline, with all data stored locally on the device.

For deploying and the repo-wide layout, see the [root README](../README.md). This file covers the app itself.

## Layout

- `index.html` — Vite entry; boots `src/main.jsx`
- `vite.config.js` — base path (`/`), build output, and the `vite-plugin-pwa` config (manifest + Workbox service worker)
- `tailwind.config.js` / `postcss.config.js` — Tailwind build + dynamic-class safelist
- `cypress.config.js` — end-to-end test config
- `src/`
  - `main.jsx` — mounts `<ClosetApp/>`
  - `App.jsx` — the root component (view state, seeding/migration, persistence wiring)
  - `styles.css` — Tailwind + CSS-variable theme
  - `seed.js` — starter items (empty by default)
  - `components/` — one file per React component
  - `lib/` — icons, storage (localStorage + IndexedDB), backup, share, hooks, logging
- `public/` — static assets copied to the site root (`icons/`, `CNAME`)
- `cypress/` — end-to-end tests (`e2e/` specs, `support/` commands, `fixtures/`)
- `dist/` — production build output (git-ignored)

## Develop

These scripts also proxy from the repo root (`npm run dev`, `npm run build`, `npm run test:e2e`, …), so you can work from either place. From here:

```bash
npm install       # first time only
npm run dev       # dev server at http://localhost:5173/
```

| Command | What it does |
|---|---|
| `npm run dev` | Dev server with hot-module reload |
| `npm run build` | Production build into `dist/` |
| `npm run preview` | Serve the built `dist/` locally (verifies the production bundle + service worker) |
| `npm run test:e2e` | Run the Cypress suite headless (boots + tears down its own dev server) |
| `npm run cypress:open` | Interactive Cypress runner (run `npm run dev` in another terminal first) |

The service worker is only generated by `npm run build`; `npm run dev` runs without one, so there's no stale-cache surprise during development.

## Test

End-to-end tests use [Cypress](https://www.cypress.io/) and live in `cypress/`. Run the whole suite:

```bash
npm run test:e2e
```

They drive the real app against the dev server and cover the major flows — items (add with photo, edit, tag, delete), filters, bulk actions, looks, collections, backup/restore, theme, and the splash screen. State is seeded deterministically before each test via the `cy.gotoApp()` command in `cypress/support/commands.js`. See the root README's **Testing** section for more.

## Storage

Two kinds of data live on the device, both scoped to the app's origin:

- **Item metadata** (names, tags, categories, outfits, collections) — **localStorage**. Small and fast.
- **Photos** — **IndexedDB**, as compressed WebP blobs (JPEG fallback on older browsers). IndexedDB's quota is much larger — typically a percentage of free disk space — so hundreds of items fit comfortably.

Photos are auto-resized to 640px on the longest edge at ~85% quality — usually 15–40 KB each. The **Backup & restore** screen shows real device-reported usage.

If you're upgrading from a much older build that stored photos in localStorage, the first launch silently migrates them into IndexedDB. Nothing for you to do.

## Offline & your data

After the first visit the service worker caches the app shell, so it works with no signal. Everything stays on the device — nothing is sent to any server. Uninstalling or clearing browser data erases your closet, so use the in-app **Backup** button to export a JSON file (items, photos as base64, outfits, collections, tags) you can re-import later.
